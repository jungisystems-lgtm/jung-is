# Architecture decision records

Each ADR should record one consequential decision in English.

- State its status, context, decision, and consequences. Include alternatives when they explain a meaningful tradeoff.
- Describe decisions that were actually made. Do not present proposals or future possibilities as accepted architecture.
- Keep ADRs short and link to the Engineering Constitution and architecture.md where relevant instead of copying them.
- Add or supersede an ADR when a difficult-to-reverse choice changes. Do not rewrite history to hide the earlier decision.
- Obtain human review for major service, API contract, tenant isolation, infrastructure, language, or database decisions.

## Change log

After changing any project-owned file in this directory, append one entry per changed file to the repository-root agent-log.md before finishing the task. Follow the format, exclusions, and append-only rule in the root AGENTS.md.
