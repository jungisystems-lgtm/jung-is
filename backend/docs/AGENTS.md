# Backend documentation instructions

Write all Markdown in English and follow the repository instructions.

- Keep architecture.md accurate about current capabilities, service boundaries, security assumptions, and open decisions.
- Distinguish implemented behavior from intended behavior. Do not present planned tenancy, auth, or provider integrations as working features.
- Keep durable principles in the Engineering Constitution, backend implementation details here, and consequential choices in adr/.
- Update documentation when backend changes make it inaccurate. Do not duplicate large sections of other documents.
- Obtain human review for major architecture, public contract, tenant isolation, infrastructure, or database decisions.

## Change log

After changing any project-owned file in this directory, append one entry per changed file to the repository-root agent-log.md before finishing the task. Follow the format, exclusions, and append-only rule in the root AGENTS.md.
