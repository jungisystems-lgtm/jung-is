# Backend ADR instructions

Record one consequential backend decision per ADR in English.

- State status, context, decision, and consequences. Include meaningful alternatives when they explain the tradeoff.
- Record decisions actually made; mark proposals as proposals and superseded decisions as superseded.
- Do not use ADRs to bypass required human approval for migrations, public contracts, tenancy, or major infrastructure changes.
- Keep the backend architecture document and the Engineering Constitution consistent with accepted decisions.

## Change log

After changing any project-owned file in this directory, append one entry per changed file to the repository-root agent-log.md before finishing the task. Follow the format, exclusions, and append-only rule in the root AGENTS.md.
